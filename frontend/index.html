Features

Everything you need to catch over-billing

A focused evaluation loop: read both documents, match the lines, validate the money, and show the evidence for every decision.

Semantic line matching

The same product found across reworded lines: USB-C Cable, 1 Meter vs Type-C Charging Cable, 100cm, scored by a local embedding model.

Deterministic money math

Quantities and unit prices are recomputed with exact decimal arithmetic. Excess rupee figures are only stated on safe ground.

Totals cross-checks

Every line total must equal quantity × price, and the stated subtotal is re-added. Failures are reported line by line.

Ambiguity to review

Near-tie candidates and contradictory SKUs are routed to NEEDS_REVIEW instead of guessed. Nothing unsafe is stated as certain.

Currency and unit safety

When currencies or quantity units disagree, the comparison basis is suppressed rather than multiplied wrongly.

Anonymous daily limits

Each browser session gets 10 analyses a day, enforced atomically at midnight IST. No account, no e-mail, no tracking.

Per-IP rate protection

Eight analyses a minute and one hundred per lifetime, per client IP — on top of the session allowance, enforced with the same atomic pattern. Rotating the anonymous session id unlocks nothing.

Speaks MCP to AI agents

A bundled MCP server wraps this API as tools, so assistants like Claude or Cursor can run an invoice review in chat and read the verdict JSON’s status, discrepancies and amounts.

Report-ready evidence

Verdicts render with a KPI strip, reconciliation and confidence visuals, and export to a branded one-page PDF report for the audit trail — no screenshots needed.

How it works

Three steps, one verdict

No configuration, no flowcharts to draw. Provide both documents and get a decision with evidence.

  1. 01

    Upload both documents

    Invoice as a PDF or image. Purchase Order as JSON or CSV, or load the bundled sample. Nothing to configure.

  2. 02

    Match every line item

    SKU first, then exact text, then fuzzy and semantic similarity. Conflicting SKUs, units or specs are contradictions, not matches.

  3. 03

    Validate, then decide

    Quantities, unit prices and totals are recomputed. You get MATCHED, DISCREPANCY_FOUND or NEEDS_REVIEW, with the numbers.

Limits & protection

Free access stays fair, enforced server-side

A public, free analyzer only stays fast and honest when abuse is stopped where it matters: inside the server, atomically, with every rejection explained.

Anonymous session allowance

Ten successful analyses per browser session per day. Capacity is reserved before the expensive work and released on any failure, so crashed requests never consume allowance. Resets at midnight IST.

10 per day · per session

Per-IP burst and lifetime caps

Session ids are client-supplied, so a second, identity-agnostic layer keys on the client IP: eight analyses per rolling minute, one hundred per database lifetime. Denied attempts are never billed, and a minute-rate rejection carries a Retry-After countdown.

8 per minute · 100 lifetime · per client IP

Fails honest, never guesses

Scanned documents without OCR tooling, currency or unit conflicts, missing fields — each returns an explicit review state or a precise dependency message, never a confident number without evidence.

3 verdict states · 0 silent fallbacks

FAQ

Questions people actually ask

Short, straight answers about how the engine works and what it does with your documents.

Does any document leave my machine?

No. Parsing, embedding and validation all run in-process on the machine serving the page. The semantic encoder is a small local ONNX model (BAAI/bge-small-en-v1.5); there are no calls to external AI services.

What are the three verdicts?

MATCHED (checked and consistent), DISCREPANCY_FOUND (a reliable match with a quantity, price or totals conflict) and NEEDS_REVIEW (weak evidence, incompatible units or currency, or missing data). NEEDS_REVIEW always wins when the numbers would be unsafe to compare.

What formats does it accept?

Invoices: PDF, PNG, JPG or WEBP up to 10 MB. Purchase orders: JSON or CSV, pasted inline or uploaded as a file. The CSV header needs description, quantity, unit_price and optionally sku, unit, line_total, po_number and currency — so the PO document header itself can be validated too. Unknown headers are rejected with the exact expected schema, never guessed.

How are the 10 analyses a day enforced?

Server-side. Each anonymous browser session reserves its allowance atomically before analysis starts, so concurrent requests cannot double-spend, and the counter resets at midnight IST.

Is there protection against scripted abuse?

Yes — a second layer rates every client IP directly: 8 analyses per rolling minute and 100 per lifetime, enforced with the same atomic database pattern. Because session ids are client-supplied, rotating them grants nothing new; the IP layer responds with 429 RATE_LIMIT_MINUTE or RATE_LIMIT_LIFETIME, and minute-limit responses include a Retry-After countdown. Denied attempts never consume allowance.

Can I automate checks or connect an AI assistant?

That is intended. The REST API is self-documented at /docs, and the repository ships invoiceguard_mcp.py — an MCP server exposing the API as analyze_invoice and usage tools for Claude Desktop, Cursor or any MCP client. Platform limits apply identically to agents and humans.

Can I use this to approve payments?

No. A MATCHED result is informational support for a reviewer; it is never a payment authorization. The prototype states that boundary in the interface, in the tests and on this page.
